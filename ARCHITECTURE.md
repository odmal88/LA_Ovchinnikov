# Архитектура сайта Льва Авксентьевича Овчинникова

Сайт создаётся как самостоятельный официальный цифровой архив Льва Авксентьевича Овчинникова.

Главный принцип: структура сайта должна сохранять разделение между маршрутизацией, визуальными компонентами, текстами, каталогом работ и изображениями. Нельзя смешивать контент Льва Авксентьевича с контентом Александра Львовича.

## 1. Назначение ключевых папок

```text
app/                  маршруты и страницы Next.js
components/           переиспользуемые визуальные компоненты
components/layout/    Header, Footer и общая оболочка
components/home/      блоки главной страницы
components/works/     каталог, карточка и страница работы
components/biography/ компоненты хронологии
components/shared/    общие элементы: форма, placeholder, служебные блоки
lib/data/             тексты сайта, каталог работ, биография
lib/types/            типы данных и справочники
public/works/lev/     изображения работ и архивные файлы Льва Авксентьевича
```

## 2. Правило разделения

### app/

Папка `app/` отвечает только за маршруты, метаданные страниц и сборку страницы из компонентов.

В `app/` не следует хранить большие тексты, каталог работ, биографические данные или описания произведений.

### components/

Папка `components/` отвечает за внешний вид и поведение блоков. Компоненты получают данные через импорт из `lib/data` или через props.

Компоненты не должны содержать реальные биографические факты, описания работ или каталожные сведения, если эти сведения можно хранить в `lib/data`.

### lib/data/

Папка `lib/data/` — основной источник текстов и данных.

Сейчас используются:

```text
lib/data/site-config.ts   общие тексты сайта, навигация, тексты страниц
lib/data/works.ts         каталог работ и функции фильтрации
lib/data/biography.ts     события биографии и функции группировки
```

Будущие разделы лучше добавлять отдельными файлами:

```text
lib/data/texts.ts
lib/data/exhibitions.ts
lib/data/memory.ts
lib/data/themes.ts
```

### lib/types/

Папка `lib/types/` хранит модели данных, справочники и локализованные подписи.

При добавлении новых полей в каталог работ сначала обновить типы, затем данные, затем компоненты.

### public/works/lev/

Все изображения Льва Авксентьевича должны храниться отдельно от изображений Александра Львовича.

Рекомендуемая структура:

```text
public/works/lev/full/       полные изображения работ
public/works/lev/thumbs/     миниатюры для каталога
public/works/lev/details/    подписи, обороты, детали
public/works/lev/archive/    архивные фото и документы
public/works/lev/exhibitions/фото экспозиций и выставочные материалы
```

## 3. Правила для каталога работ

Каталог работ хранится в `lib/data/works.ts`.

Каждая работа должна иметь устойчивый `id` и `slug`.

Минимальные поля:

```text
id
slug
artist
title
period
technique
material
dimensions
genre
descriptionShort
attributionStatus
isPublic
```

Изображения подключаются через поля:

```text
imageFull
imageThumb
imageDetails
```

Пример:

```ts
imageFull: "/works/lev/full/lo-001-title-full.webp",
imageThumb: "/works/lev/thumbs/lo-001-title-thumb.webp",
imageDetails: ["/works/lev/details/lo-001-signature.webp"],
```

Не использовать случайные stock-изображения как работы художника.

Если изображение ещё не добавлено, оставить поля изображения пустыми. Компоненты покажут нейтральный placeholder.

## 4. Правила для текстов

Тексты страниц хранятся в `lib/data/site-config.ts`.

Короткие служебные подписи допустимы в компонентах только если они не являются содержательным редакционным текстом.

Если текст будет редактироваться содержательно, он должен быть вынесен в `lib/data`.

## 5. Правила биографии

Биография хранится в `lib/data/biography.ts`.

Если факт не подтверждён, писать осторожно:

```text
сведения уточняются
требует архивной проверки
будет дополнено после сверки документов
```

Нельзя выдумывать:

- место рождения;
- учебные заведения;
- членство в организациях;
- выставки;
- даты создания работ;
- цитаты художника.

## 6. Правила семейной линии

Сайт Льва Авксентьевича не должен превращаться в предисловие к сайту Александра Львовича.

Допустимая логика:

```text
Лев Авксентьевич — самостоятельный художник.
Связь с Александром Львовичем — важный слой семейной художественной преемственности.
Каждый художник раскрывается в собственном масштабе и на собственном сайте.
```

Недопустимо:

```text
Лев важен только как отец Александра.
Александр является главным смыслом биографии Льва.
Работы двух художников смешиваются в одном каталоге.
```

## 7. Правила формы контактов

Пока форма технически не подключена к обработчику, она не должна имитировать реальную отправку.

Текущий режим формы: заготовка обращения. При нажатии пользователь получает уведомление, что форма пока не подключена.

После подключения формы нужно явно определить:

- куда отправляются данные;
- где они хранятся;
- кто получает уведомление;
- как обрабатывается согласие на персональные данные.

## 8. Правила будущих правок

Перед правкой текста сначала проверить, где он реально живёт:

1. `lib/data/site-config.ts`
2. `lib/data/works.ts`
3. `lib/data/biography.ts`
4. компонент в `components/`
5. страница в `app/`

Не переносить утверждённые тексты обратно в страницы или компоненты, если они уже вынесены в `lib/data`.
